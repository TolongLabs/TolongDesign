## What it is

Good UI catalogs interface patterns and A/B test examples related to conversion.
Patterns are organized by screen and subject, while test entries describe
observed changes and reported outcomes.

The site offers public previews and a paid membership for the full library. Its
evidence is useful for generating experiment ideas, but a result from one
product or audience is not a universal design rule.

Use it as research input for a hypothesis. Check the context, measure, and test
setup before proposing an implementation for a TolongLabs project.

## How to use

- Browse patterns by screen or filter tests by topic and metric to find examples
  related to the user journey.
- Open a pattern or test and record the interface context, audience, changed
  element, measured outcome, and limitations.
- Write a project-specific hypothesis that connects the pattern to an observed
  user problem.
- Run a controlled experiment when the traffic and instrumentation support one;
  otherwise treat the pattern as a qualitative idea, not proof.

## When to use it

- Use it when a team is forming conversion hypotheses for signup, pricing,
  checkout, or landing-page work.
- Skip it when the primary question is accessibility, visual identity, or
  browser behavior; use Inclusive Components, Abduzeedo, or web.dev.

## Agent notes

- The full library is paywalled; do not claim access to details that are not
  shown in the public preview.
- Reported A/B outcomes depend on context, sample, and metric. Do not present a
  pattern as causal proof for another product.
- The site is a research reference, not a component package or programmatic API.
- For client work, translate the reference into a measurable hypothesis and get
  stakeholder approval for the experiment design.
