## What it is

Component Gallery is a repository for comparing how design systems handle common
interface components. It organizes component patterns and links them to the
systems that implement them.

The site exposes searchable entries with technology and feature information,
including accessibility notes and examples. The checked home page reported 60
components, 95 design systems, and 2,671 examples.

It is a research aid rather than a package to install. Use it to compare
interaction patterns, terminology, and accessibility guidance before writing a
project-specific component brief.

Pricing and access were checked on 2026-10-07.

## How to use

1. Search for the component pattern you need, such as a carousel or popover.
2. Filter or scan entries by design system, technology, and features such as
   accessibility or implementation examples.
3. Compare several systems and note the shared behavior, meaningful differences,
   keyboard expectations, and responsive states.
4. Turn those notes into a short TolongLabs brief with the intended behavior and
   visual direction; implement against the project stack rather than treating
   the gallery as source code.

No published install command or code snippet could be verified. Use the public
site as a reference only until the publisher documents a current implementation.

## When to use it

- Use it during discovery when deciding how a common component should behave
  across a product or design system.

- Skip it when you need installable production code; use a library such as
  [HeroUI](../component-libraries/heroui.md) or
  [Kibo UI](../component-libraries/kibo-ui.md).

## Agent notes

- Treat entries as pointers to the original design systems, not as a
  consolidated implementation.
- Capture the source system and specific behavior you are borrowing in the
  project brief.
- Check the original source for current code, accessibility details, and licence
  terms.
